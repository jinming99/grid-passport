# A 500 MW request is not a forecast

- Data-center demand is rising faster than the grid can plan around it.
- Utilities cannot plan from raw requested MW alone.
- Grid Passport turns private operational facts into planning-grade disclosures.

![](apps/web/public/hackathon/hackathon-grid-hero.png){ width=75% }

# Demand is rising. Planning certainty is not.

- U.S. data centers used about **4.4%** of national electricity in **2023**.
- DOE / LBNL project that share to reach **6.7% to 12% by 2028**.
- Dominion's queue pressure shows the same pattern at the utility level: big numbers arrive faster than planning-grade visibility.

# The federal record keeps naming the same gap

## DOE

- Proprietary planning visibility is missing.
- Speculative and duplicative requests distort the planning picture.

## NERC

- Large loads have become a reliability and operations issue, not only an interconnection issue.
- Operators need earlier warning about ramp, trip, and reconnection behavior.

## ERCOT

- Requested MW is not treated as planning truth.
- The market is moving toward more structured large-load disclosure.

**Punch line**

The bottleneck is not only generation. It is information flow under privacy and competitive constraints.

# The form is becoming more operational

- Large-load disclosure is moving beyond identity and nameplate MW.
- Utilities want:
  - energization timing
  - ramp and reconnection behavior
  - backup generation and BESS details
  - flexibility and redistribution capability
- Dominion already asks for many of the same categories in its facility interconnection requirements.

# Static forms still fail when behavior changes

- July 10, 2024: about **1,500 MW** of Northern Virginia data-center load disappeared in seconds during the NoVA event.
- NERC's lesson was not "ask for a bigger PDF."
- The lesson was: operators need a standing coordination channel for large-load behavior.

**Punch line**

This is not just a forecasting problem. It is a data-sharing problem.

# Grid Passport closes the loop

Applicant intake

- baseline filing
- sensitive fields stay local

Signed disclosure

- derived planning outputs
- policy-governed visibility
- cryptographic receipt

Utility coordination back

- outage notices
- upgrade schedules
- operational constraints

Signed memory

- disclosure
- actual
- residual
- better calibration next time

**Punch line**

The data center keeps the playbook. The utility gets the answer. The regulator verifies the chain.

# What the demo proves

- **Act 1:** Owl Compute completes the baseline filing without leaking competitive fields.
- **Act 2:** a six-week training surge is disclosed weeks before it lands on the grid.
- **Act 3:** the utility sends a signed notice back through the same path.
- **Act 4:** residuals become calibration data instead of disappearing into email.
