# Grid Passport / WhisperGrid Harness

**Working product name:** Grid Passport  
**Working brand/style codename:** WhisperGrid  
**Tagline:** **Truth without disclosure.**

Grid Passport is a **confidential coordination OS for large-load interconnection**.

It solves a specific bottleneck:

> utilities need forecast-quality information; applicants often cannot reveal it raw.

This harness is designed so you can build a prototype that feels:

- problem-first
- AI-agent centric
- privacy credible
- demo theatrical
- production-intentional

## One-sentence pitch

**Grid Passport turns private load, site, and flexibility data into utility-usable proofs — without requiring either side to surrender secrets.**

## The three demo promises

1. The applicant can submit a credible request without revealing raw strategic data.
2. The utility can make a meaningfully better planning decision using derived signals only.
3. The whole flow is governed by explicit release policy, audit logs, and visible evidence — not “trust us”.

## The wow moments you must preserve

- A raw private field enters the system and disappears from the utility view
- A derived proof appears instead
- A public evidence swarm auto-pulls DEQ / FEMA / parcel / permitting context
- A release policy visibly explains why one party can see one thing but not another
- A counterfactual toggle shows how flexibility changes the planning outcome

## Hard constraints

Do **not** build first:
- a full ISO dispatch simulator
- autonomous live equipment control
- complicated cryptography demos nobody can follow
- chat-only UX
- a generic “AI for the grid” dashboard

Do build:
- a guided intake
- a dual-view workflow
- a policy-governed confidential boundary
- a clean evidence packet
- a single powerful scenario comparison

## Core taste

The style should feel like:

**air-traffic control × cryptographic vault × environmental permit dossier**

Use playful energy in the framing, not in the decision surfaces.

## 48-hour build order

### Day 1
- Build the intake wizard
- Build the dual-view request object
- Build the public-data side panel
- Build the derived-proof card
- Build one synthetic Virginia case study end-to-end

### Day 2
- Add explicit release policies
- Add audit / attestation panel
- Add one counterfactual scenario
- Add eval dashboard + red-team results
- Polish motion, copy, and stage timing

## A strong final demo feels like this

In 2–3 minutes, the viewer should conclude:

> “I was expecting a better intake form or a demand-response optimizer.  
> What they actually built is a trusted planning layer the market is missing.”
